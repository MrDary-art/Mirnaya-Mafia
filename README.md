# Арена переговоров

Учебный симулятор переговоров на **Node.js + TypeScript + React**. Одна кодовая база для локального браузерного приложения и будущего сайта. Основной путь: **миссия → подготовка → решение → последствия → разбор → упражнение → повтор**. Продукт перерабатывается по [полному ТЗ](ТЗ_Арена_переговоров_единый_учебный_путь.md).

## Запуск

Нужны **Node.js 24.x** и npm 11.x. Все команды выполняются из корня проекта:

```sh
npm ci
npm run build
npm start
```

Откройте <http://127.0.0.1:3000>. Для быстрого входа используйте `demo@example.com` / `1234`: при каждом запуске сервера его тренировки, награды и упражнения сбрасываются. Аккаунт `pinggos` / `4321` сохраняет прогресс между запусками и входит по логину без почты. У существующего аккаунта пароль обновляется при следующем запуске без удаления прогресса; прежние сеансы входа завершаются. Сервер слушает только `127.0.0.1`, создаёт SQLite-базу `data/arena-v2.db` и обслуживает собранный интерфейс. Путь к используемой базе также печатается при старте. Для дальнейших запусков достаточно `npm start`.

Для разработки: `npm run dev` (интерфейс на <http://127.0.0.1:5173>, API на порту 3000). Проверка: `npm run check`. Данные базы, `.env` и сборки не должны попадать в Git.

## Что уже работает в новой версии

- Публичный лендинг, регистрация, вход и выход. Пароли хешируются Argon2id, авторизация хранится в серверной сессии через HttpOnly cookie; изменяющие запросы требуют CSRF-токен.
- Настройки профиля: отображаемое имя и приоритетная тема практики сохраняются в браузере отдельно для каждого аккаунта. Выход требует подтверждения.
- Единое оформление **Solana × Solflare**: тёмный фон Solflare, оранжевые градиенты, анимированная фигура Solana в первом экране ближе к центру; ниже при прокрутке — парящая карточка Solflare. Края подсветки видео растушёваны, текст и разделы плавно появляются при прокрутке. После входа личный кабинет использует графику Solflare и жёлтый акцент.
- Ярлык **«Оформление» справа** позволяет настроить цвета дизайна, иконок и объектов, вращение/парение/паузу, скорость и выразительность. Сохранены пять фонов: композиция Solana × Solflare, прежняя 3D-спираль VARA, сияние, сетка и чистый фон. По умолчанию включён тёмный режим; светлый и системный доступны в оформлении и настройках профиля. Палитры публичных страниц и личного кабинета сохраняются отдельно (`arena-appearance-v3:public` / `arena-appearance-v3:workspace`) и синхронизируются между вкладками. Прежние настройки v1/v2 остаются в браузере, но не переопределяют новое оформление.
- Экран «Сегодня» с одной рекомендуемой миссией, продолжение незавершённой попытки и рекомендация по последнему разбору.
- Каталог **15 перенесённых сценариев**. Их тексты, варианты, переходы, эффекты и концовки лежат в `packages/content/scenarios/` с версией контента.
- Подготовка, сценарный разговор, четыре серверные метрики (`trust`, `goal`, `control`, `eq`), последствия решений, отчёт, короткое упражнение, повтор и история.
- Идемпотентность действий и наград. За первое завершение сценария начисляется 25 XP, за второе — 10 XP, за дальнейшие — 0 XP. Сценарная тренировка не вызывает ИИ и работает без интернета после установки.
- Тесты сценариев и полного маршрута API. `npm run check` собирает пакеты и запускает проверки.

Референсы и происхождение графики указаны в [описании оформления](apps/web/public/backgrounds/README.md). Все ресурсы доступны локально; внешние шрифты, скрипты и запросы к референсам при работе приложения не нужны. Основное оформление не требует WebGL: Solflare нарисован CSS, Solana использует локальное видео (665 КБ) со статическим кадром при недоступном воспроизведении. Видео останавливается вне экрана и в скрытой вкладке. Системное уменьшение движения и ручная пауза отключают также анимации появления; содержимое остаётся доступным.

Спираль остаётся отдельным вариантом и использует исходную геометрию VARA, текстуру и окружение; происхождение файлов указано в [описании ресурсов спирали](apps/web/public/backgrounds/vara/README.md). Three.js загружается отдельно только при её выборе; при недоступном WebGL показывается статическая графика. Для повторной подготовки модели: `node scripts/prepare-spiral.mjs` после `npm ci`.

## Структура

| Путь | Назначение |
| --- | --- |
| `apps/web/` | React/TypeScript интерфейс и Vite |
| `apps/server/` | Node/TypeScript API, авторизация, SQLite, статический сервер |
| `packages/contracts/` | проверяемые входные схемы API и общие типы |
| `packages/domain/` | сценарные переходы, метрики, отчёт, рекомендации |
| `packages/content/scenarios/` | 15 сценариев, перенесённых из прежнего движка |
| `tests/` | модульные и интеграционные тесты |
| `docs/migration-audit.md` | карта переноса и незакрытые пункты ТЗ |

## Состояние переработки

Это **рабочий первый этап**, а не готовый публичный выпуск по всему ТЗ. Старый FastAPI/backend и старый React/frontend удалены из рабочей версии; они доступны в истории Git. Следующие возможности **ещё не перенесены**: свободный диалог и собеседование с GigaChat/Ollama, распознавание и озвучивание речи, 10 глав и 60 уровней, комнаты и WebRTC, друзья и сообщения, магазин и достижения, администрирование, импорт прежней SQLite-базы, PostgreSQL, почтовое подтверждение и восстановление доступа. Разделы «Путь развития» и «Люди» честно показывают статус разработки.

**Старую базу не подменяйте новой.** Для существующих пользователей сначала нужен отдельный проверенный скрипт миграции с резервной копией и сверкой данных. До этого прежнюю версию следует держать доступной через Git. Не публикуйте текущую сборку как завершённую интернет-версию: нужны PostgreSQL, HTTPS, централизованные лимиты, почтовый вход и проверки доступа сетевых функций.

Конфигурация локального режима: `ARENA_DB_PATH` (путь к SQLite), `HOST` (по умолчанию `127.0.0.1`), `PORT` (по умолчанию `3000`). Не задавайте `ARENA_MODE=site` без полноценной инфраструктуры и завершения интернет-этапов ТЗ.
