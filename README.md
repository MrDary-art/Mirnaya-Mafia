# Арена переговоров

Веб-приложение для тренировки деловых переговоров. В сценарном режиме игрок выбирает ответы, видит реакцию собеседника и изменения четырёх метрик (`trust`, `goal`, `control`, `eq`), а после завершения получает отчёт. Сценарии работают локально без API-ключей и внешних LLM.

Стек: FastAPI, SQLAlchemy, SQLite и Alembic на сервере; React, Vite и Tailwind CSS в браузере. Дополнительные разделы включают обучение, профиль, свободную практику с ИИ и комнаты для двух участников. Для ИИ и голоса нужны отдельные сервисы или модели; для сценариев они не нужны.

## Быстрый запуск

Нужны Python 3.12, Node.js 20+ и npm. Команды выполняются из **корня проекта**. Сервер и интерфейс запускаются в двух терминалах.

### Windows PowerShell

```powershell
python -m venv backend/.venv
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
cd backend
./.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000
```

Во втором терминале, также из корня проекта:

```powershell
cd frontend
npm ci
npm run dev
```

### macOS / Linux

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
cd backend
.venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

Во втором терминале, также из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Откройте <http://localhost:5173>. Vite направляет запросы `/api` на сервер по адресу <http://127.0.0.1:8000>; проверка сервера — <http://127.0.0.1:8000/api/health>, схема API — <http://127.0.0.1:8000/docs>. При первом запуске сервер создаёт SQLite-базу в `data/arena.db` и демонстрационные учётные записи. Для локальной проверки: `demo` / `demo`; для входа в админку: `admin` / `admin`. Эти пароли публичны и подходят только для локальной разработки.

Файл `.env` для сценарного режима не требуется. Если нужны собственные настройки, скопируйте `backend/.env.example` в `backend/.env` и задайте значения перед запуском сервера. Сервер читает этот файл при запуске **из каталога `backend`**. В первую очередь замените `SECRET_KEY` на случайную строку длиной не менее 32 символов. Файл `.env` и содержимое `data/` с пользовательскими данными не должны попадать в репозиторий.

## Как устроен проект

| Путь | Назначение |
| --- | --- |
| `backend/app/` | FastAPI, маршруты, хранение сессий, сценарный движок и интеграции |
| `backend/app/data/scenarios/` | Локальные сценарии переговоров |
| `backend/alembic/` | Миграции схемы базы данных |
| `frontend/src/` | Интерфейс и клиент API |
| `models/` | Голосовые модели через Git LFS |
| `data/` | Локальная база и приватные файлы во время работы |
| `docs/` | Актуальные технические заметки и архив прежней документации |

Сервер владеет состоянием сессии, метриками и отчётом; интерфейс отображает данные и отправляет действия игрока. Доступны три локальных сценария: увольнение, переговоры о зарплате и скидка при продаже. Настройка сессии — `/setup`, каталог — `/scenarios`, история — `/history`, админка — `/admin`.

## Проверка и сборка

Из корня проекта:

```powershell
cd backend
./.venv/Scripts/python.exe -m pytest -q
```

На macOS/Linux используйте `.venv/bin/python -m pytest -q`. Проверка сборки интерфейса: `cd frontend`, затем `npm run build`. После сборки и перезапуска API сервер может раздавать готовый интерфейс по адресу <http://127.0.0.1:8000/>; при разработке используйте Vite на порту 5173.

На существующей базе перед обновлением приложения выполните из `backend`: `./.venv/Scripts/python.exe -m alembic upgrade head` (macOS/Linux: `.venv/bin/python -m alembic upgrade head`). Новая база создаётся приложением при первом запуске.

## Дополнительные возможности

- **Свободный диалог с ИИ:** скопируйте `backend/.env.example` в `backend/.env`, впишите свой `GIGACHAT_CREDENTIALS` (Authorization key из кабинета GigaChat, без публикации в Git) и выберите `GIGACHAT_SCOPE` и `GIGACHAT_MODEL`, доступные вашему тарифу. Для личного доступа используется `GIGACHAT_API_PERS`; модель по умолчанию `GigaChat-3-Ultra` может быть недоступна на другом тарифе. Перезапустите backend и проверьте `/api/health`; при недоступности GigaChat приложение пробует локальный Ollama по `OLLAMA_URL` с моделью `OLLAMA_MODEL`. Для Ollama сначала установите и запустите сам сервис и загрузите выбранную модель. Без обоих провайдеров сценарный режим продолжает работать, а в свободном диалоге отображается ошибка подключения.
- **Голос в свободном диалоге:** из корня проекта выполните `python scripts/prepare_voice.py` после установки backend-зависимостей. Команда получает веса Whisper и Piper через Git LFS либо из официальных хранилищ моделей, проверяет SHA-256 и пробует загрузить обе модели; `--check-only` проверяет готовность без сети. Кнопка «Начать голосовой разговор» распознаёт вашу речь в текст и отправляет её ИИ; для текстовой переписки включите «Озвучивать ответы ИИ». Разрешите микрофон в браузере; для удалённого адреса нужен HTTPS. Подробности — в [описании моделей](models/README.md) и [документе о голосе и комнатах](docs/voice-mode.md).
- **Комнаты двух участников:** для связи между устройствами нужны HTTPS и, при некоторых сетях, TURN. Локальный запуск на одном компьютере не проверяет связь через разные сети.

Для размещения в интернете задайте собственный `SECRET_KEY`, `CORS_ORIGINS` и `ROOM_ALLOWED_ORIGINS`, уберите публичные демонстрационные учётные записи и настройте постоянное хранилище. Готовый `deploy/deploy.sh` — исторический пример, а не проверенный способ развёртывания текущей версии.

## Секреты и пользовательские данные

Проверка файлов этой копии проекта не обнаружила действующих API-ключей или приватных ключей. Места, требующие внимания перед публикацией сервиса:

| Где | Что находится |
| --- | --- |
| `backend/app/config.py`, `backend/.env.example` | Стандартный ключ подписи JWT в коде и пример замены в шаблоне; для публичного сервера задайте свой `SECRET_KEY` через окружение или `backend/.env` |
| `backend/app/auth.py`, `frontend/src/pages/Login.jsx` | Публичные демонстрационные логины и пароли, включая администратора `admin` / `admin` |
| `backend/.env.example` | Имена переменных `GIGACHAT_CREDENTIALS`, `GPT2GIGA_API_KEY` и параметры подключения; реальные значения не включены |
| `backend/certs/russian_trusted_root_ca.pem` | Публичный корневой сертификат, не приватный ключ |
| `data/`, `backend/app/config.py` | SQLite-база и путь к записям комнат; реальные данные возникают при запуске и исключены через `.gitignore` |
| `frontend/src/api.js` | JWT текущего пользователя сохраняется в `localStorage` браузера под именем `arena_token` |

В этой копии нет каталога `.git`, поэтому история коммитов не проверялась. Перед публикацией в сети отдельно проверьте историю исходного репозитория на старые секреты.

Указатель по остальным документам: [docs/README.md](docs/README.md).
