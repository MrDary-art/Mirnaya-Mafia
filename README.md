# Арена Переговоров

## Версия GigaChat + голос + парные комнаты

Ветка `version/gigachat-voice-pvp-2026-09-19` сохраняет отдельную версию на базе `0176788`.
Она содержит прямое подключение GigaChat, локальные Whisper/Piper, анкету и новый чат,
отчёты с результатом переговоров, комнаты двух людей с WebRTC и парные собеседования
с одинаковыми вопросами и лимитом 15 минут. Изменения команды из более новой `main`
в эту версию не объединены.

Для запуска на Windows из корня этой ветки:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt

npm.cmd ci
npm.cmd run build
cd ../backend
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Общий ключ GigaChat включён в `backend/gigachat.public.env` по прямому указанию
владельца репозитория и автоматически загружается при старте. Публичный корневой
сертификат API включён в `backend/certs/`. Создавать `.env` для этого не требуется.
Локальный `.env` и переменные окружения могут переопределять общую настройку.
Персональная база и остальные локальные секреты не включены в Git. Обе модели размещены в `models/`:
веса Whisper и Piper загружены в GitHub LFS, остальные файлы хранятся обычным способом.
Скрипт подготовки получает веса из этой ветки через Git LFS и проверяет их SHA256.
Используйте `git clone` с установленным Git LFS; ZIP может содержать только указатели.

Сайт: http://127.0.0.1:8000/ · [Подробности голоса и комнат](docs/voice-mode.md).
Проверены backend тесты, frontend build, реальные ответы GigaChat и локальная озвучка.
WebRTC требует проверки с камерами двух участников; для другого устройства нужен HTTPS,
а для соединения через разные NAT может потребоваться TURN.

Ниже сохранено описание исходного сценарного MVP; перечень roadmap относится к нему.

Интерактивный симулятор деловых переговоров. Ядро MVP — **сценарный офлайн-режим** с предразмеченными метриками (TKI, Гарвардский метод, взвешенная уверенность). LLM — опциональный интерфейс свободного диалога, не источник вердикта.

Оценка считается по формулам и объясняется в отчёте. Это не «просто чат с нейросетью».

## Что умеет MVP

- Три сценария, главный — **«Увольнение без конфликта»** (HR, 6 шагов, ветвление).
- Пресеты быстрого старта и экран настройки (базовые поля сразу, остальное под «Расширенные»).
- Метрики 0–100: Доверие, Цель, Контроль, EQ + Confidence = `(0.5·Goal + 0.3·Trust + 0.2·Control)`.
- Отчёт: вердикт, график, 3 ошибки с альтернативами, 2 рекомендации, карта TKI, BATNA, игровой профиль.
- Админка: правка контекста сценариев без правки JSON.
- История, кабинет, лимит 10 активных сессий.
- Онлайн-режим (v1.1): GigaChat через gpt2giga → Ollama → офлайн-сценарий. Без ключей продукт всё равно играбелен.

Не в MVP (roadmap): PvP, UGC, рейтинг, голос, ежедневный вызов, Big Five.

## Почему нет Big Five

Короткий опросник и классификация нейротизма по тексту диалога психометрически невалидны. В отчёте — **игровой профиль** на TKI, без претензии на диагностику.

## Быстрый запуск (Windows / macOS / Linux)

Нужны Python 3.11+ и Node 18+.

```bash
# backend
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env   # Windows
# cp .env.example .env   # Unix
uvicorn app.main:app --reload --port 8000

# frontend (второй терминал)
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173

Демо-пользователи (создаются при старте API):

- `demo` / `demo`
- `admin` / `admin`

Офлайн-сценарий **не требует** интернета и API-ключей. Vite проксирует `/api` на порт 8000.

Тесты:

```bash
cd backend
pytest -q
```

Миграции (после смены схемы на уже существующей базе):

```bash
cd backend
alembic upgrade head
```

На чистой установке FastAPI сам создаёт таблицы (`create_all`). Alembic нужен, чтобы не ломать данные при обновлениях.

## Формулы (ядро продукта)

Дельты техник (первая ×1.0, вторая ×0.7, третья ×0.5):

- Trust: слушание +3, эмпатия +2, сотрудничество +2, конкуренция −5, агрессия −3, перебивание −4
- Goal: критерии +4, BATNA +3, SPIN +2, уступка без выгоды −2 (−3 в зарплатных), позиционный торг −3
- Control: вопросы +3, пауза +2, структура +2, оправдания −3, агрессия −2
- EQ: отражение +4, спокойствие +2, грубость −5, игнор сигналов −3

Метрика всегда в `[0, 100]`. Реплики старше 5 ходов при пересчёте ×0.5. В сценарном режиме на вариантах стоят уже калиброванные дельты — LLM не вызывается.

## Архитектура LLM (если включите онлайн)

1. gpt2giga → GigaChat (таймаут 7 с)
2. Ollama `qwen2.5:7b`
3. Офлайн-реплика текущего шага сценария

Невалидный JSON анализатора → rule-based парсер по ключевым словам. Мусор/таймаут → дельты 0 или fallback, сессия не падает.

Переменные: см. `backend/.env.example`.

## Деплой

### Вариант A — VPS (рекомендуется)

Схема: Nginx 443 → FastAPI 8000 → (опционально) gpt2giga 8090 / Ollama 11434 → SQLite-файл.

1. Код в `/opt/arena/`
2. Frontend: `cd frontend && npm ci && npm run build` → раздать `frontend/dist` как корень сайта **или** положиться на то, что FastAPI сам отдаёт `frontend/dist`, если каталог существует.
3. Backend venv + gunicorn, unit-файл: `deploy/arena.service`
4. Nginx: `deploy/nginx.conf` — `proxy_pass` на `http://127.0.0.1:8000` **без** хвостового `/`, чтобы сохранить префикс `/api` (это намеренное отличие от черновика промпта: иначе API сломается).
5. `certbot --nginx`
6. Каталог данных: `/var/www/arena/data`, владелец `www-data`

gpt2giga (если нужен онлайн): `docker compose --env-file .env -f deploy/base.yaml --profile PROD up -d`

### Вариант B — Vercel + Railway

- Frontend: Root = `frontend`, `VITE_API_URL=https://<railway>/api` — нет: фронт ходит на `/api/...`, поэтому задайте `VITE_API_URL=https://<railway-host>` без суффикса (код сам добавит `/api`).
- Backend: Root = `backend`, volume `/data`, `DB_PATH=/data/arena.db`, `CORS_ORIGINS=https://<vercel-domain>`

## Решения, которых не было в ТЗ

- Рядом с обязательными таблицами: `sessions.state` (JSON сцены), `users.is_admin`, `app_settings` (админ-контекст). Иначе нельзя честно продолжить сессию и править бриф без правки файлов.
- Пользовательские пресеты UI хранятся в `localStorage`, не в БД.
- Nginx не снимает `/api`.
- Дополнительно к HR-ядру — два коротких, но цельных сценария под пресеты «торг» и «зарплата», чтобы экран настройки не врал.
- Режим хаоса в UI не включён: без влияния на метрики это декорация; лучше не показывать.
- Презентация для жюри: `docs/PITCH.md` (pptx в репозиторий не кладём — соберите слайды из этого файла за 10 минут).
