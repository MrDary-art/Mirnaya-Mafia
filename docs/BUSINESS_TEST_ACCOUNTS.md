# Тестовая компания «Додо»

В ветке поставляется воспроизводимый набор данных: владелец, пять участников,
три задания на каждого участника и шесть завершённых попыток с настоящими
отчётами движка. Это обычные аккаунты с разными корпоративными правами.

## Запуск после получения ветки

```bash
git fetch origin
git switch --track origin/sukhovskiy.a.a/business-testing-oct18
```

Установите зависимости и подготовьте API обычным для проекта способом. Перед
запуском сервера примените миграции из корня `backend`:

```bash
python scripts/run_local.py alembic upgrade head
python scripts/run_local.py uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале **из корня репозитория** выполните:

```bash
python backend/scripts/seed_business_demo.py
```

На Windows используйте `py -3.12` вместо `python`, если так установлен Python.
Сам скрипт использует только стандартную библиотеку Python; работающему API
нужны обычные зависимости `backend/requirements.txt`.

Затем запустите интерфейс в третьем терминале:

```bash
cd frontend
npm install
npm run dev
```

В PowerShell при запрете запуска `npm.ps1` используйте `npm.cmd`.
Откройте `http://127.0.0.1:5173/`.

Набор данных создаётся явной командой. При обычном старте сайта тестовые
пользователи автоматически не добавляются. На отдельном тестовом сервере можно
указать адрес API: `--base-url https://test.example.org --allow-remote`.
API ожидается по указанному адресу, без `/api` в конце.

## Что создаётся

1. Компания «Додо · тестовая команда», отрасль «Обучение переговорам», 25 мест.
2. Владелец и пять участников с ролями из таблицы.
3. Заявки участников через обычную регистрацию по коду компании и их одобрение владельцем.
4. Три корпоративных задания со сценарием `sales_discount_01`:
   - «Тест: согласовать скидку»;
   - «Тест: повторные переговоры»;
   - «Тест: следующий шаг».
5. По одному назначению каждого задания каждому участнику — 15 назначений.
6. По одному завершённому сценарию для каждого из пяти участников и дополнительная
   завершённая попытка второго задания для Елены — всего шесть отчётов.
7. Девять оставшихся назначений для самостоятельного прохождения на свежей базе.

Порог прохождения — 60, максимум три попытки; выдача сертификата включена и зависит
от выполнения серверных условий. Сроки назначений — через 3, 4 и 5 дней от запуска.
Варианты ответов выбираются скриптом, а баллы, метрики, история, завершение,
результаты и отчёты рассчитываются существующим серверным движком. Скрипт не
записывает нарисованные показатели в базу.

На чистой контрольной установке получены шесть отчётов, средний балл 56,
метрики: доверие 53, цель 56, контроль 67, EQ 48. На уже заполненной локальной
компании результаты могут отличаться: ранее завершённые попытки сохраняются.

ID компании, пользователей, заданий и попыток определяет база. Код компании
генерируется при создании, поэтому его нужно брать из результата команды или
боковой панели владельца. Локальный ID `6` и код `59G6-86J2Z` не обязательны для
чужой установки и не зашиты в скрипт.

## Проверка интерфейса и прав

### Владелец — dododo

- Откройте «Профиль → Аналитика»: доступны результаты компании.
- Откройте «Команда»: видны шесть человек и карта иерархии.
- Откройте результаты завершённых попыток и подробные отчёты сотрудников.
- Через аватар переключитесь в личную Арену, затем обратно в компанию без нового входа.
- В нижней части боковой панели отображается `Код: …`.
- В календаре доступно создание встречи 1×1 и групповой игры «Совет решений».

### Администратор — dododo_admin

- Есть собственное завершённое задание с кнопкой «Посмотреть отчёт».
- Доступны корпоративные результаты и управление в пределах роли.
- В AI-профиле показываются имя Марии и читаемое название её роли.
- «Каталог профессий» находится в настройках, а не во вкладках обучения.

### Менеджер обучения — dododo_hr

- Есть собственное завершённое задание и отчёт.
- Доступны обучение и корпоративная аналитика по существующим разрешениям.
- В настройках доступен каталог профессий; общие настройки компании скрыты,
  если у роли нет `manage_company`.

### Сотрудники — dododo_1, dododo_2, dododo_3

- В обучении видны собственные назначения и их статусы.
- У Алексея и Дмитрия по одному завершённому отчёту, у Елены два.
- Оставшиеся задания можно начать и пройти самостоятельно.
- Запрос общей корпоративной аналитики возвращает 403.
- Список попыток не раскрывает чужие отчёты.
- Код приглашения компании не выдаётся без соответствующих прав.

Набор специально содержит разные результаты, чтобы проверить пройденные и
непройденные задания, баллы, метрики и остаток попыток. Руководитель не получает
права на чужие личные тренировки: здесь речь о корпоративных назначениях.

## Повторный запуск и диагностика

- Скрипт входит в созданные аккаунты и переиспользует компанию и задания по названию.
- Завершённые целевые назначения повторно не запускаются; отчёты не дублируются.
- При несовпадении роли или владельца существующего аккаунта выполнение останавливается
  с ошибкой вместо перезаписи прав и паролей.
- При ограничении частоты запросов скрипт соблюдает `Retry-After`; ожидание до минуты нормально.
- Запуск не является одной транзакцией: если произошла ошибка сети, часть данных
  может уже сохраниться. Исправьте причину и выполните ту же команду ещё раз.
- Готовность проверяется чтением всех завершённых отчётов владельцем и проверкой
  запрета общей аналитики для трёх сотрудников.
- Для сохранения сводки без access-токенов:

```bash
python backend/scripts/seed_business_demo.py --output data/private/dododo-summary.json
```

Скрипт создаёт аккаунты, задания и отчёты. Ранее вручную назначенные встречи из
локальной базы в этот набор не входят; их можно создать через новый календарь.
Локальная база, почтовые токены, настройки SMTP и реальные пользовательские записи
в Git не передаются.
