# Отчёт: «Переиграй решающий момент»

Дата: 27 сентября 2026. Ветка: `feat/decisive-moment-replay`.

## Что внедрено

В офлайн-тренажёр встроена первая версия «машины времени переговоров»: после завершения сценария пользователь возвращается к одному важному решению, отвечает иначе и получает сравнение двух попыток. Это реальная отдельная сессия с продолжением разговора, а не заранее показанный «идеальный ответ».

| Сценарий | Точка возврата | Что исследует пользователь |
| --- | --- | --- |
| Увольнение без конфликта | Ход 4, `step_4` | Признать интерес сотрудника к репутации, игнорировать его или усилить давление |
| Торг за скидку | Ход 3, `s3` | Обсудить критерии и обмен, уступить в цене, давить сроком или пригрозить выходом |

Для каждого ответа в этих точках добавлена собственная авторская реакция собеседника. После реакции продолжается существующий сценарий; новые длинные независимые ветви не добавлялись. Начисление метрик не менялось: используются эффекты выбранного варианта, без дополнительного начисления за реакцию.

## Как попробовать

1. Открыть приложение: `http://127.0.0.1:5173` или собранную версию `http://127.0.0.1:8000`.
2. В сценариях выбрать «Увольнение без конфликта» или «Торг за скидку» и начать новое прохождение **без хаоса**.
3. Дойти до отчёта. В нём появится блок «Переиграй решающий момент»: вопрос собеседника, прежний ответ и объяснение, почему этот выбор важен.
4. Нажать «А если ответить иначе?». Откроется отдельная попытка в сохранённой точке. Прежний вариант помечен и недоступен для повторного выбора.
5. Выбрать другой ответ и завершить разговор. Сравнение покажет обе реплики, реакции собеседника, объяснения, исходы и изменение четырёх метрик.

Можно уйти со страницы или перезагрузить браузер. Кнопка в исходном отчёте станет «Продолжить переигрывание». Завершённые и остановленные попытки остаются в истории, а исходный отчёт содержит ссылки на свои переигрывания.

## Что именно сравнивается

- **Сразу:** разница метрик после ответа в точке возврата. Если истёк таймер, это явно отмечается: штраф тоже влияет на разницу.
- **Итог:** разница после завершения обеих попыток. Она зависит также от последующих решений, а не только от одной изменённой реплики.
- **Слова и последствия:** фактические выбранные ответы, сохранённые авторские реакции и комментарии к выбору, затем итог каждого разговора.
- Одинаковый итог допустим. Интерфейс не обещает, что другой ответ обязательно приведёт к победе, и поясняет, что это модель сценария, а не прогноз поведения реального человека.

## Сохранность и ограничения

- Исходная сессия, её стенограмма, метрики и сохранённый отчёт не перезаписываются.
- Перед важным ответом сервер сохраняет историю, сообщения, метрики, счётчики, настройки и снимок сценария. Новая попытка восстанавливается из этих данных; клиент не передаёт собственные метрики или снимок.
- Будущее редактирование каталога не меняет сохранённый сценарий переигрывания.
- Повторное нажатие кнопки возвращает уже активную попытку вместо создания дубликата. Проверяется принадлежность сессии текущему пользователю.
- Переигрывания не выдают повторные звёзды, XP, достижения и завершения учебных узлов; исключены из карьерной статистики, профиля и личной аналитики. В истории они явно помечены.
- Режим доступен только для двух указанных обычных офлайн-сценариев. Не включён для хаоса, корпоративных заданий, учебных финалов и онлайн-диалогов. Вложенное переигрывание переигрывания запрещено — новые эксперименты запускаются из исходного отчёта.
- Старые отчёты без сохранённой точки не реконструируются приблизительно: вместо кнопки возврата показано объяснение и предложение пройти сценарий заново.
- Как и существующая блокировка сессий, защита от одновременного создания действует внутри одного процесса backend. Для многопроцессного production-развёртывания нужна межпроцессная блокировка/ограничение в БД; это отдельная работа.
- Общие административные и корпоративные сводки в этой задаче не перерабатывались.

## Проверки

- Полный backend: **132 теста прошли**, включая **9 новых** тестов переигрывания.
- Frontend: **66 тестов прошли**.
- Production-сборка: `npm.cmd run build` — успешна.
- `git diff --check` — без ошибок.
- Playwright, desktop 1440×900 и mobile 390×844: оба исходных сценария пройдены через UI по 20 ходов, после возврата — ещё 17 и 18 ходов соответственно.
- Проверены ошибка создания и повторная попытка, продолжение из исходного отчёта, перезагрузка страницы, отключение прежнего ответа, разные реакции, неизменность исходной сессии и баланса, метка в истории и отсутствие горизонтального переполнения.
- Браузерные прогоны успешно завершены и на dev-сервере, и на собранной production-версии через backend. Ошибок JavaScript не обнаружено. Результаты заключительного прогона: `.cache/decisive-replay/results.json`.
- Сохранились прежние предупреждения Starlette/httpx, SQLAlchemy в тесте демо-чата и о размере Three.js-чанка. Новые зависимости не добавлялись.

Нагрузочный тест, все комбинации дальнейших решений и проверка скринридером не проводились. Для браузерных прогонов созданы отдельные локальные тестовые аккаунты; пользовательские сессии не использовались и не удалялись.

## Изменённые файлы этой функции

| Файлы | Назначение |
| --- | --- |
| `backend/app/features/decisive_replay.py` | Две авторские точки, снимки состояния, создание попытки, сравнение и проверки доступности |
| `backend/app/services.py` | Подключение снимков и реакций к существующему игровому циклу, завершение без повторных наград |
| `backend/app/routers/game.py` | Новый POST `/api/sessions/{id}/replay`, дополнительные данные отчёта и каталога, блокировка обработки выбора |
| `backend/app/features/progression.py` | Исключение переигрываний из карьерной статистики |
| `backend/app/routers/meta.py`, `backend/app/routers/insights.py` | Отметка в истории, исключение из профиля и личной аналитики |
| `frontend/src/components/DecisiveReplay.jsx`, `decisive-replay.css` | Блок момента, сравнение, состояния ожидания/ошибки, мобильная компоновка |
| `frontend/src/pages/Report.jsx`, `Play.jsx` | Встраивание в отчёт и игровой экран, защита выбора прежней реплики, подсказка режима |
| `frontend/src/pages/History.jsx`, `Scenarios.jsx` | Обозначение учебных попыток и анонс возможности |
| `backend/tests/test_decisive_replay.py` | Регрессионные проверки |
| `frontend/scripts/verify-decisive-replay.mjs` | Воспроизводимая браузерная проверка |
| `frontend/dist/index.html` | Обновлённая production-сборка |

Схема БД и входной контракт `SessionSettings` не менялись, новая миграция не нужна. Добавлены обратно совместимые поля ответов: `decisive_replay` в каталоге, `replay` в отчёте, серверная метка в настройках попытки, `original_choice` у варианта и `practice_replay` в истории. Прежние незакоммиченные исправления аудита сохранены; в main ничего не отправлялось.

## Повторный запуск проверок

Из `backend`: `python -m pytest -q`.

Из `frontend`: `npm.cmd run build`, затем при запущенном приложении `node scripts/verify-decisive-replay.mjs`. Для собранной версии в PowerShell: `$env:ARENA_PREVIEW_URL = 'http://127.0.0.1:8000'` перед запуском скрипта. Путь Chrome переопределяется через `ARENA_CHROME_PATH`.

Браузерный скрипт создаёт тестовые аккаунты и сессии: запускать только на локальном или тестовом окружении.
