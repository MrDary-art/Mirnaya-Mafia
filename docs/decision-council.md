# Совет решений

Режим доступен по `/council`, короткая демонстрация — `/demo/council`.
Администратор назначает модераторов в `/admin/council`. Назначенный игровой
аккаунт получает корону и может открывать набор в свои публичные или закрытые
встречи. Частные встречи компании создаёт только `Company.created_by`, при
наличии активного членства. У обычного пользователя нет формы создания; сервер
также отклоняет такой запрос. Администратор может опубликовать слот, выбрав
назначенного модератора. Организатор выбирает, играет ли сам или выступает
ведущим без игровой роли. Для обычной игры нужны четыре подтверждённых игрока.

## Проведение

1. Создать встречу за 72 часа — 60 дней. Закрытую встречу собрать приглашениями
   по логинам. Для корпоративной встречи перейти из «Совместной практики»:
   приглашения доступны сотрудникам компании, событие видно в их календарях.
2. За 48 часов подтвердить участие. За сутки неполный состав отменяется;
   собранный состав фиксируется. До открытия карточек ведущий может вручную
   распределить четыре разные роли. Организатор видит все вводные и редактирует задания, обычный игрок — свою карточку.
3. За два часа открываются роли; за 15 минут — подготовка. Прочитать карточку,
   нажать «Я ознакомился» и «Готов к началу». Микрофон подключается отдельной
   кнопкой; камера включается по желанию. Звук не записывается.
4. Организатор запускает игру в назначенное время. После пяти минут ожидания
   можно предложить место отсутствующего резервисту. Система передаёт его роль
   только после принятия предложения; готовность и ознакомление проходят заново.
   Предложение действует десять минут, затем переходит следующему резервисту.
5. Обсуждать в общем звонке или чате, при необходимости переписываться лично.
   Предложения публикуются на общий стол. Устные и личные договорённости нужно
   явно перенести в общий документ.
6. Каждый подтверждает сохранённую версию соглашения. Изменения снимают голоса.
   Конфликт версий нельзя затереть сохранением старого черновика. После четырёх
   согласий появляется проверка выполнимости и разбор по публичным текстовым
   свидетельствам. Личные переписки и заметки не используются в разборе.

Фоновая проверка сроков работает каждые 15 секунд; обращения к встрече также
проверяют переходы. Напоминания появляются в уведомлениях сайта. `.ics` позволяет
добавить событие во внешний календарь.

## Полномочия организатора

Назначения находятся в `council_moderators`. Отзыв администратором сразу запрещает
создание и управление встречами; роль «организатор» в старом составе сама по себе
полномочий не даёт. Модератор управляет только собственными встречами.
Создатель компании управляет собственными корпоративными встречами.

Пульт позволяет в любой незавершённой встрече:
- завершить игру, сохранив неутверждённый документ и текстовый разбор;
- исключить игрока и закрыть ему повторный вход, сообщения, голосование и звонок;
- заблокировать микрофон и сообщения, отдельно запретить камеру;
- изменить роль, название, цель/ТЗ, закрытые факты, ограничения и вопросы.

При занятой роли происходит обмен. Изменение задания снимает готовность и
ознакомление, сбрасывает голоса и повышает версию документа. Участник обязан
прочитать обновление перед голосованием. Если изменены вводные, итог требует
ручной оценки организатора: старые числовые ограничения не объявляются новым
источником истины. Личные сообщения и заметки организатору не раскрываются.

Медиа-ограничения приходят с серверным опросом каждые 2 секунды: клиент выключает
свои дорожки, получатели также приглушают/скрывают запрещённые потоки. Исключение
удаляет сигналы и закрывает соединения. Снятие запрета не включает устройства
автоматически. Медиа передаётся P2P; реальный межсетевой звонок проверяется отдельно.

## Звонок

WebRTC соединяет участников напрямую, сервер передаёт только адресные сигналы.
Сигналы хранятся ограниченное время и доступны только получателю в своей встрече.
При отключении останавливаются микрофон, камера и соединения; можно подключиться
заново. Для доступа к устройствам нужен HTTPS или localhost.

Используется существующая настройка `room_ice_servers_json`. Для соединений через
разные сети может понадобиться TURN-сервер; его адрес и учётные данные задаются
в конфигурации установки, в код их добавлять не нужно. Тестирование на реальных
устройствах и сетях проверяет доступность конкретной инфраструктуры отдельно.

## Демонстрация

Три шага: раздать роли, обсудить условия, собрать и проверить решение.
Три карточки: клиент, производство, финансист. Полномочия руководителя проекта
вынесены в общие правила ведущего. QR-коды ведут на карточки, доступные без входа.
Для телефонов нужен доступный им адрес сайта; localhost на телефоне не ведёт на ПК.
Карточки предназначены для очного обсуждения, документ заполняется на экране
ведущего. Свободную роль может представлять явно обозначенный ИИ-персонаж;
при недоступности провайдера используется помеченная сценарная реплика.
Демонстрация не создаёт обычную запланированную встречу и не влияет на её результаты.

## Проверка и запуск

Миграции совета: `0040_decision_council`, `0041_council_completion`,
`0045_council_merge`, `0046_council_moderation`. Merge сохраняет обе истории:
обновление возможно как с main `0044_company_mode_usage`, так и с прежней
локальной версии совета `0041_council_completion`. Итог — один Alembic head.
Перед обновлением рабочей базы сохранить резервную копию, затем из `backend`
выполнить `python -m alembic upgrade head`.

Из `backend`: `python -m pytest -q` или `python -m pytest -q tests/test_council.py`.
Из `frontend`: `npm.cmd run build`, затем `npm.cmd run dev` для разработки.
API: `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`.
