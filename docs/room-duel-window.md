# Два собеседования: час на прохождение

## Трудоустройство с ИИ · 1×1

Оба участника претендуют на одну должность в одной компании. В форме задаются компания, должность и необязательные требования вакансии. Цель на сервере общая: получить работу. Роли, цели и названия сценариев переговоров не переносятся в этот режим. Сессии создаются с `practice_kind: job_interview`, общим планом вопросов, одинаковым лимитом времени и выключенным помощником.

ИИ оценивает ответы по четырём одинаковым критериям с проверкой дословных цитат. Сервер определяет победителя по сумме этих оценок. При равных баллах сохраняется ничья; отсутствие ответов не считается проигрышем. Общий итог сообщает, кому достался оффер в симуляции. Личный отчёт показывает все сохранённые эпизоды, цитаты, альтернативы, рекомендации и стенограмму. Личные рекомендации второго кандидата не раскрываются. PDF использует финальный отчёт комнаты и включает общий итог и сравнение.

Блоки «Как меняются показатели» и «Ход интервью» в комнате трудоустройства убраны. При сбое ИИ отчёт не подставляет советы из постороннего сценария переговоров.

Регрессионные проверки:

```powershell
cd backend
python -m pytest -q tests/test_hiring_report.py tests/test_job_interview.py tests/test_rooms.py tests/test_room_v2.py tests/test_room_comparison.py tests/test_room_roles.py tests/test_room_bookings.py tests/test_narrative_report.py tests/test_online_outcome.py tests/test_voice.py
```

Для сквозной браузерной проверки запустить из корня `python backend/tests/fixtures/hiring_duel_server.py`, затем из `frontend` запустить Vite с `VITE_API_PROXY_TARGET=http://127.0.0.1:8018` на порту 5188 и выполнить `node scripts/verify-hiring-duel.mjs`. Этот сервер использует отдельную тестовую БД в `.cache/hiring-qa/`, двух вымышленных пользователей и подменённые провайдеры ИИ/озвучки. Реальные создание, приглашение, отдельные попытки, обработка отчётов и PDF проходят через HTTP и БД. Проверяются ширины 1440 и 390 пикселей, отсутствие переполнения и ошибок JavaScript, раскрытие стенограммы, приватность рекомендаций и повтор встречи. Проверка не подтверждает доступность GigaChat и реального микрофона на боевом сервере.

## Таймер и обработка

Новые комнаты `duel` сохраняют `duel_window_minutes: 60` в существующем JSON состояния. Миграция таблиц не требуется. Старые комнаты без этого поля сохраняют прежний таймер.

1. Оба участника входят и подтверждают готовность. После наступления выбранного времени сервер открывает час.
2. Каждый самостоятельно нажимает «Начать моё собеседование». `POST /api/rooms/{id}/attempt/start` сохраняет начало и личный дедлайн. Повторный запрос не перезапускает таймер.
3. Личная попытка ограничена выбранной длительностью и концом общего часа. До старта и после дедлайна сервер отклоняет ответы, включая общий API текстовых/голосовых сессий.
4. Первый завершивший видит зал ожидания. Второй может независимо начать или продолжить. После обоих завершений (или истечения часа) фоновая задача готовит отчёты.
5. Сравнение получает реальные протоколы обоих. ИИ выбирает A/B/ничью и возвращает каждому объяснение с проверяемой цитатой. Общий вердикт хранится отдельно от личных рекомендаций и не меняет игровые метрики.
6. Если нет ответов одного участника, победитель не определяется. При сбое ИИ личные отчёты доступны, сравнение можно повторить.

Переговоры людей также переходят к анализу автоматически после завершения. Обратная связь больше не блокирует подготовку отчёта.

Демо `/rooms/demo` иллюстративное: зал ожидания и результаты вымышлены и явно подписаны. Реальные комнаты доступны через `/rooms`.

Локальный сервер запускается с одним worker: блокировки изменения JSON комнаты синхронизируют HTTP-запросы и фоновую проверку таймеров внутри процесса. Для нескольких API workers понадобятся распределённые/транзакционные блокировки.

Проверки: `pytest tests/test_room_comparison.py tests/test_room_roles.py tests/test_rooms.py tests/test_room_v2.py -q`; `npm run build`; `node scripts/verify-room-waiting.mjs` (браузерные данные комнат подменены, проверяются состояния интерфейса). Один реальный запрос сравнения GigaChat также проверен отдельно. Полный звонок двух пользователей и аудиомодели этой проверкой не покрыты.
