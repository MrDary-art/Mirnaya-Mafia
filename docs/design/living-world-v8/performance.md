# Производительность: текущая проверка

Изменения после жалобы на лаги:

- Начальный JavaScript после разделения маршрутов: 1031 KB → 394 KB minified (301 → 125 KB gzip). Тяжёлый код отчётов/аналитики и Three.js загружается только по необходимости.
- Главная запрашивает текущий и соседний постеры, а не все восемь сразу. Дальние главы монтируются при приближении прокрутки.
- На программном/неподходящем WebGL 3D-модель ~5.3 MB и Three.js не загружаются: вместо неё на первом экране показывается прозрачный WebP-кадр из того же рига (desktop ~27 KB, mobile ~11 KB). На обычном WebGL остаётся исходная 3D-сова; на слабом аппаратном устройстве используется low-poly GLB и ограничиваются FPS/пиксели буфера.
- На очень слабом устройстве по умолчанию `static` + `economy`; у статичного Canvas буфер 1×1. На среднем слабом устройстве — `calm` + `economy`. Пользователь может изменить выбор вручную.
- Смена суток отключена по запросу: нет runtime-загрузки облаков/масок и вычисления солнца.

[`evidence/current/weak-device.json`](evidence/current/weak-device.json): Chrome headless, WebGL отключён, имитированы 2 ядра/2 GB/Save-Data, 1366×768. Главная и `/scenarios`, `/training`, `/history`, `/profile`, `/practice` открылись без ошибок страницы; пять переходов заняли 566–1406 ms **в этой локальной конфигурации**, не являются обещанием для другого ноутбука. На первом экране запрошены только Hero, соседний AI, ветка и WebP-кадр совы. Запросов sky masks/clouds/GLB нет.

[`evidence/current/verification.json`](evidence/current/verification.json) фиксирует эмуляцию 1920/2560/3840 и mobile DPR2; реальные 4K и телефон аппаратно не проверены. Профиль Chrome headless/SwiftShader не переносится на физический GPU. Нужны замеры на устройстве пользователя, особенно cold cache, долгой прокрутки и работы GPU без аппаратного ускорения.
