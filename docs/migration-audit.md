# Карта переноса

Новая рабочая версия находится в `apps/` и `packages/`; исходный код прежней версии сохранён в истории Git ветки `master`. Эта карта фиксирует фактическое состояние и неперенесённые функции.

| Прежняя область | Состояние в npm-версии |
| --- | --- |
| 3 подробных и 12 шаблонных сценариев | Все 15 развернуты в отдельные JSON, тексты/ветви/эффекты сохранены; метрики и отчёт реализованы заново. Нужно сравнить эталонные оценки и концовки на выборке прежних прохождений. |
| Авторизация и SQLite | Новая локальная схема и Argon2id; **старые аккаунты и данные ещё не импортированы**. |
| Свободный ИИ, GigaChat/Ollama, собеседование, Whisper/Piper | Не перенесены. Нужен серверный шлюз с лимитами, адаптеры провайдеров и тесты. |
| Уроки, упражнения, 10 глав / 60 уровней | Сейчас работает микроупражнение после отчёта; старое содержание и уровни не перенесены. |
| Комнаты 1×1, независимые интервью, WebRTC | Не перенесены. Нужны контракты событий, приватность целей, TURN и проверка двух сетей. |
| Друзья, сообщения, приглашения | Не перенесены. |
| XP, ранги, звёзды, магазин, достижения | Только журнал XP с ограничением повторов; остальное не перенесено. |
| Администрирование | Не перенесено. |
| Личные тренировки из опыта | Не реализованы. |
| Хаос `type` / `id` | Механика не перенесена; перед переносом зафиксировать единый контракт и тест. |

## Порядок завершения

1. Зафиксировать эталонные расчёты старого сценарного движка, перенести уроки/уровни, предметные действия `provide`/`calculate`/`record_agreement`, затем проверить отчёты и рекомендации.
2. Ввести интерфейс хранилища, миграции схем и PostgreSQL-адаптер; отдельно провести репетицию переноса старой SQLite-базы с резервной копией, сверкой и планом возврата.
3. Добавить серверный ИИ-шлюз, лимиты и журнал расхода, затем голос и собеседование. До подключения провайдера не выдавать шаблонный ответ за ИИ.
4. Перенести комнаты, WebRTC, друзей, сообщения, профиль, награды и админку с проверками прав на каждом API и событии.
5. Проверить обе конфигурации, HTTPS, доступность, производительность, восстановление и критерии приёмки из ТЗ до публичного переключения.
