# Интерактивные истории

Раздел `/stories` — короткие переговорные истории с выбором роли и развязками. Он отличается от суточных фото/видеоисторий социальной ленты `/feed` и использует API `/api/stories`.

## Что реализовано

Шесть редакционных ситуаций: бесплатные правки, повышение зарплаты, признание вклада, скидка, срочная пятничная задача и задержанная оплата. В каждой две роли, восемь узлов и несколько исходов; путь занимает два–три решения. Редакционные материалы не изображают публикации реальных пользователей. Лайки, комментарии, подписки и прохождения считаются по базе, без предварительной накрутки.

Лента поддерживает поиск, темы и вкладки «Для вас», «Подписки», «Сохранённое», «Мои истории». «Для вас» здесь означает общую хронологическую выдачу, а не персональные рекомендации. Пагинация этого раздела — `offset/limit` с `next_offset`.

Авторская студия `/stories/new` создаёт одну сцену, одну роль и три варианта с отдельными исходами. Многошаговые графы доступны для просмотра, но не редактируются упрощённой студией. Серверный черновик требует полностью заполненного валидного графа. Публикация: `draft → pending → published` либо `rejected`; возвращённый материал можно изменить и отправить снова. Опубликованные истории не редактируются; модератор может скрыть историю или закрыть жалобы. Очередь находится в `/admin/stories`.

## Архитектура и контракты

| Область | Файл |
| --- | --- |
| Редакционные графы | `backend/app/data/stories.py` |
| Проверка графа, переходы, метрики и безопасные DTO | `backend/app/features/stories.py` |
| Истории, попытки, реакции, комментарии, подписки, жалобы | `backend/app/story_models.py` |
| Авторизация и HTTP | `backend/app/routers/stories.py` |
| Лента и студия | `frontend/src/pages/Stories.jsx`, `StoryStudio.jsx` |
| Карточка, разбор и общие элементы | `frontend/src/components/features/stories/` |

Используются существующие JWT, `users.id`, `AsyncSession`, `api.js` и `useAuth`. Новых зависимостей именно для интерактивных историй нет. GigaChat, Ollama и API-ключи не нужны.

Граф содержит `roles`, `nodes`, `endings`; вариант — `id`, `text`, `next`, `effect`, `explanation`. Сервер запрещает циклы, недостижимые элементы, неизвестные переходы и роли без альтернативных исходов. Поддерживаются до двух ролей, до 30 узлов и 2–4 ответа в узле.

Канонические показатели: `trust`, `goal`, `control`, `eq`. Начальные значения — 50; единственный источник изменения — выбранный `effect` с целыми значениями от −20 до 20. Сервер ограничивает итог диапазоном `[0, 100]`. Название подхода в студии помогает выбрать эффект; повторного начисления за теги нет.

Попытка сохраняет снимок графа, историю ответов и ревизию. Клиент отправляет `node_id`, `option_id`, `revision`; повторный или устаревший ответ получает `409`. Уникальный частичный индекс исключает две активные попытки одной роли для одного читателя. При открытии восстанавливается активная попытка, иначе последний завершённый разбор.

| API | Назначение |
| --- | --- |
| `GET/POST /api/stories` | Лента / создание черновика |
| `GET/PUT /api/stories/{id}` | История и попытка / изменение черновика |
| `GET /api/stories/{id}/draft`, `POST …/submit` | Граф автора / отправка на проверку |
| `POST /api/stories/{id}/attempts` | Начать или продолжить выбранную роль |
| `GET /api/stories/attempts/{id}`, `POST …/choices` | Собственная попытка / ответ |
| `PUT /api/stories/{id}/like`, `PUT …/save` | Идемпотентное состояние `{active: boolean}` |
| `PUT /api/stories/authors/{id}/follow` | Подписка на автора |
| `GET/POST /api/stories/{id}/comments` | Обсуждение |
| `DELETE /api/stories/comments/{id}`, `POST /api/stories/{id}/report` | Удаление своего комментария / жалоба |
| `GET /api/admin/stories/queue`, `POST /api/admin/stories/{id}/moderate` | Проверка, публикация, возврат, скрытие, закрытие жалоб |

## Приватность

Попытки доступны только их владельцу; публикация не раскрывает его решения. Черновики доступны автору и отдельным административным маршрутам. Учитываются взаимные блокировки. Для закрытого профиля публичные истории показывают username вместо закрытого отображаемого имени. Жалобы видит модератор: API отдаёт до десяти последних причин на историю без идентификатора заявителя. Самомодерация запрещена.

Показатели и разбор описывают поведение в конкретной игровой ситуации, не личность или психометрический диагноз. Публикации не начисляют XP или звёзды. Развилки не гарантируют такой же результат в реальном разговоре.

## Миграция и запуск

Схема добавлена миграцией `0032_interactive_stories` после `0031`. Перед обновлением существующей установки остановите запись в БД и сделайте согласованную резервную копию настроенной SQLite. Не заменяйте миграции вызовом `create_all`; последующие миграции проекта также применяются через `upgrade head`.

Используйте интерпретатор, в котором установлены зависимости `backend/requirements.txt`. В локальном окружении может быть настроен системный `python`; наличие каталога `.venv` само по себе не подтверждает установку пакетов.

```powershell
cd frontend
npm run build
cd ../backend
python -m alembic current
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

После запуска: `http://127.0.0.1:8000/stories`. Для разработки frontend можно отдельно запустить `npm run dev`; существующий Vite proxy направляет `/api` на backend. При старте редакционные истории добавляются идемпотентно по `slug`, без перезаписи существующих записей.

## Проверка

Из `backend`:

```powershell
python -m pytest -q tests/test_stories.py
python -m pytest -q tests/test_scenarios.py tests/test_metrics.py
```

Целевые тесты проверяют графы, публикацию, приватность, восстановление разбора, однократное применение эффектов, конкурентные старты и ответы, реальные идемпотентные реакции, комментарии, блокировки и ограниченную выдачу жалоб.

Браузерный smoke-сценарий запускается из `frontend`: `node scripts/verify-stories.mjs`. Он изменяет данные, поэтому нужен отдельный локальный QA-сервер с одноразовой БД и тремя тестовыми аккаунтами: читатель, автор, администратор с изменённым стандартным паролем. Переменные окружения: `ARENA_QA_READER`, `ARENA_QA_AUTHOR`, `ARENA_QA_MODERATOR`, общий `ARENA_QA_PASSWORD`, `ARENA_PREVIEW_URL` и явный `ARENA_QA_DISPOSABLE=1`. Не направляйте сценарий на рабочую БД; секреты в репозитории не сохраняются. Эта инструкция описывает запуск, а не утверждает, что конкретный прогон уже прошёл.

## Границы версии

Здесь нет рекомендательной ML-модели, видеохостинга, совместного редактирования или универсального визуального редактора многошаговых графов. Обсуждения обновляются запросами, не отдельным WebSocket-каналом. Счётчик прохождений означает начатые попытки, включая авторские проверки, а не уникальных читателей. Общая социальная лента и суточные истории документируются отдельно.
