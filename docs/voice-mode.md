# Локальный голос и парные комнаты

## Один участник с ИИ

После анкеты `/practice?session=…` получает тему и цель из настроек сессии. Браузер запрашивает разрешение на микрофон только после нажатия «Начать голосовой разговор». `AudioWorklet` продолжает читать звук во время распознавания и ожидания GigaChat; во время ответа Piper захват ставится на паузу, чтобы не отправить голос ИИ обратно в диалог. Пауза около 550 мс либо 30 секунд непрерывной речи завершает один фрагмент; фрагменты помещаются в очередь и обрабатываются в порядке записи. Во время записи чат показывает анимированный индикатор. Части расшифровки появляются до ответа ИИ, а две галочки показываются после сохранения реплики на сервере.

`POST /api/sessions/{id}/voice` принимает mono PCM16, 16 кГц, до 40 секунд. `faster-whisper` работает локально и передаёт текст в ту же функцию, что и обычное сообщение. Оригинальное аудио не сохраняется. Ответ GigaChat сохраняется в историю; `POST /api/sessions/{id}/speak` проверяет, что текст действительно принадлежит оппоненту этой сессии, и возвращает WAV из локального Piper. Клиент воспроизводит его как аудиофайл. Ответы, оценка и отчёт рассчитываются сервером; голосовой ввод не имеет отдельной логики подсчёта.

Для нового чата `POST /api/sessions/{id}/turn-stream` и `voice-stream` передают события JSON построчно: принятие реплики, части расшифровки, части ответа, готовые предложения с WAV и итог после сохранения. GigaChat вызывается один раз с `stream=true`; служебный разбор скрыт от чата, проверяется сервером и только затем влияет на метрики. Текст ответа показывается по мере генерации, а в голосовом режиме буквы открываются примерно в темпе проигрываемого предложения. Точное совпадение каждого слова со звуком без временных меток фонем Piper не гарантируется. Старые маршруты остаются для остальных потребителей.

Локальный голос: `ru_RU-dmitri-medium` (Piper, 22,05 кГц). Модель и конфигурация включены в `models/piper/`. Whisper base включён в `models/whisper-base/`. Веса размером 63 МБ и 145 МБ размещены в GitHub LFS этой ветки. Для получения полного содержимого выполните из корня Git-копии:

```powershell
git lfs install
git lfs pull
backend/.venv/Scripts/python.exe scripts/prepare_voice.py --check-only
```

Backend читает обе модели из `models/`, без скачивания с Hugging Face и без старого кэша. При запуске сервера обе модели загружаются в память; первый запрос не ждёт их загрузки. На сервере с 4 vCPU и 2,9 ГБ RAM Whisper base работает в `int8`: два потока CPU на распознавание и два параллельных работника для двух участников. Параметры `STT_CPU_THREADS` и `STT_WORKERS` можно изменить через окружение. Экземпляр Piper и голос `ru_RU-dmitri-medium` остаются прежними. Для экономии RAM запускайте один процесс Uvicorn; несколько процессов загрузят копию моделей в каждый.

## Два участника

`/rooms` создаёт один из двух форматов с кодом приглашения. В комнате «Люди ↔ люди» GigaChat готовит две роли, люди общаются текстом либо через WebRTC видео и голос. Каждый браузер параллельно режет свой микрофон на фрагменты и отправляет их на локальное распознавание: транскрипции попадают в общую историю и в отдельный разбор каждого. Сигналы WebRTC передаются через авторизованные маршруты комнаты, медиапоток идёт между браузерами. Комната хранится в базе и рассчитана на двух вошедших пользователей.

В «двух собеседованиях с ИИ» оба участника получают одну вакансию, цель и список из четырёх одинаковых вопросов. У каждого свой приватный диалог и голосовой режим; таймер начинается при входе второго человека. После 15 минут либо после завершения обоих диалогов сервер делает два отчёта, сравнение и учебное решение «ПРИНЯТ/НЕ ПРИНЯТ». Числовая оценка и решение остаются на сервере; GigaChat объясняет результаты. Внутри любой сессии метрики имеют только `trust`, `goal`, `control`, `eq` и диапазон 0–100.

## Запуск и ограничения

На новом ПК установите зависимости и выполните из корня проекта
`backend/.venv/Scripts/python.exe scripts/prepare_voice.py`. Скрипт загрузит обе модели
и проверит файлы Piper по SHA256. Команда с `--check-only` проверяет уже загруженные
модели без обращения к сети. Порядок сборки frontend и настройки ключа описан в README.

Из `backend/` запустите `.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`. Собранный frontend доступен на `http://127.0.0.1:8000/`. Общий `GIGACHAT_CREDENTIALS` находится в `backend/gigachat.public.env`; локальный `backend/.env` может его заменить. Корневой сертификат API находится в `backend/certs/`. При старте backend получает OAuth access token и обновляет его до истечения срока. `/api/health` показывает статус без ключа.

На `localhost` браузер разрешает камеру и микрофон. Для теста двух людей на одном ПК используйте два разных профиля браузера или обычное окно и приватное окно: вкладки одного профиля делят токен входа. Для открытия комнаты с другого устройства нужен доступ к серверу по локальной сети и HTTPS для медиа разрешений; TURN сервер в локальной версии не настроен, поэтому WebRTC за разными NAT не гарантирован. Голосовые фрагменты обрабатываются по очереди; при разговоре быстрее, чем успевают Whisper и GigaChat, задержка и использование памяти растут. Страница показывает длину очереди. Нет потоковой транскрипции внутри фрагмента и серверного долговременного хранения исходного аудио.
