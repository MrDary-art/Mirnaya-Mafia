# Голос и онлайн 1 на 1

## Разговор с ИИ

`/practice` использует локальный Whisper для распознавания и Piper `ru_RU-dmitri-medium`
для озвучки. Браузер непрерывно читает микрофон через `AudioWorklet`, делит речь по
паузе и отправляет PCM16 16 кГц. Во время ответа ИИ захват приостанавливается, чтобы
голос Piper не вернулся в диалог. Текст и озвучка используют один серверный ход и одну
систему метрик.

## Онлайн 1 на 1 V2

`/rooms` поддерживает два формата:

- **Переговоры людей**: общий текстовый чат и WebRTC звонок, разные роли и приватные
  цели. Сервер анализирует только реплики соответствующего автора.
- **Два интервью с ИИ**: одинаковая вакансия, snapshot сценария и восемь вопросов,
  два независимых диалога и два приватных отчёта. Командный балл равен сумме двух
  индивидуальных результатов и не подменяет их.

Жизненный цикл: `lobby → active → feedback → processing → finished`. Комната стартует
только после входа второго участника, наступления назначенного времени, проверки
устройств и явной готовности обоих. Длительность задаётся от 2 до 30 минут. Обновление
страницы восстанавливает серверное состояние и deadline.

Приглашение можно отправить кодом, из чата друзей или из публичного профиля друга.
До присоединения показываются формат, публичное описание сценария, время и длительность.
Личная цель второй стороны, её ответы и отчёт не раскрываются.

## Сигналинг, STUN и TURN

WebSocket `/api/rooms/{id}/ws` авторизуется JWT через WebSocket subprotocol; токен не
попадает в query string. Origin проверяется по `ROOM_ALLOWED_ORIGINS`. SDP и ICE
передаются через сервер, медиапоток остаётся peer-to-peer. REST signaling сохранён как
совместимый fallback и журнал для восстановления после переподключения.

Локально достаточно STUN по умолчанию. Для пользователей за разными NAT нужен TURN:

```env
ROOM_ICE_SERVERS_JSON=[{"urls":["stun:stun.example.org:3478"]},{"urls":["turns:turn.example.org:5349"],"username":"arena","credential":"replace-me"}]
ROOM_ALLOWED_ORIGINS=https://arena.example.org
```

TURN credential хранится только в окружении сервера. Для production используйте
короткоживущие TURN credentials, TLS и лимиты трафика.

## Запись и приватность

Запись выключена по умолчанию. Пользователь даёт отдельное согласие, после чего
браузер записывает **только собственный микрофон** через `MediaRecorder`. Чанки по 4
секунды отправляются с `segment_id`, индексом, интервалом и SHA256. Повторная отправка
того же чанка идемпотентна; несовпадающий checksum отклоняется. После stop последний
`dataavailable` дожидается загрузки, затем отправляется manifest.

Запись хранится вне static каталога в `ROOM_RECORDINGS_PATH`, скачивается только
владельцем через авторизованный endpoint и помечается сроком хранения
`ROOM_RECORDING_RETENTION_DAYS`. Максимальный объём одной записи задаётся
`ROOM_MAX_RECORDING_BYTES`. Для production каталог должен быть доступен только
пользователю systemd сервиса; резервное копирование и внешнее object storage должны
сохранять тот же owner scope.

## Отчёты и рейтинг

После завершения пользователь может отправить или пропустить feedback. Feedback не
влияет на игровой счёт. Тяжёлый отчёт выполняет фоновая durable job с повторными
попытками, поэтому страницу можно закрыть. Клиент получает только свой отчёт и общий
командный результат. Публикация рейтингового результата требует согласия обоих.

Рейтинговая запись содержит `challenge_key`, версию scoring, snapshot сценария и
лучший командный результат. Неполные, custom и несопоставимые попытки не должны
смешиваться с проверенными заданиями.

## Reverse proxy

Nginx должен передавать WebSocket upgrade и увеличенный timeout:

```nginx
location /api/rooms/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
    client_max_body_size 6m;
}
```

Для сервера 4 vCPU / 2.9 ГБ RAM запускайте один Uvicorn worker: Whisper и Piper
загружаются в память процесса. Фоновая job loop стартует вместе с приложением.
Перед запуском production выполните `alembic upgrade head`.

## Проверка на двух устройствах

1. Откройте HTTPS сайт в двух браузерных профилях и войдите под разными аккаунтами.
2. Создайте комнату, проверьте preview приглашения и войдите вторым аккаунтом.
3. Разрешите устройства, убедитесь, что без двух нажатий «Готов» таймер не стартует.
4. Проверьте видео, mute/camera off, переподключение сети и ICE restart.
5. При включённой записи убедитесь, что каждый скачивает только собственный файл.
6. Завершите встречу, отправьте feedback, обновите страницу во время processing и
   проверьте появление личного отчёта.
