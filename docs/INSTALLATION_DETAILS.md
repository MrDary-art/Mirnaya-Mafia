# Подробная установка и обслуживание

Быстрый запуск и актуальные команды: [Установка за несколько шагов](INSTALLATION.md).

## Начните здесь

Есть две независимые установки:

1. **Сайт** — на вашем Windows-компьютере или Ubuntu-сервере. Здесь пользователи,
   отчёты, GigaChat, база, голос Дмитрия и запасное распознавание Tiny.
2. **Внешний Whisper** — только на Ubuntu VM с выделенной NVIDIA GPU. Он получает
   записи с сайта, распознаёт речь и возвращает текст. Сайт на этой VM не нужен.

Сначала установите сайт и войдите в `/admin`. Подключать МИРЭА можно позже.
Открытие репозитория в браузере само по себе не запускает сервер.

## Где скачать готовую сборку

Откройте [Releases](https://github.com/MrDary-art/Mirnaya-Mafia/releases).
Ищите предварительный релиз **install-v2026.09.28.3**. В разделе Assets нужны:

- `arena-install-v2026.09.28.3.zip` — приложение с готовым интерфейсом;
- `arena-install-v2026.09.28.3.zip.sha256` — контрольная сумма;
- `install-windows.ps1` или `install-ubuntu.sh` — установщик.

Не выбирайте автоматически добавленные **Source code (zip/tar.gz)**: это исходники,
а не установочный комплект. Если релиз ещё собирается, проверьте
[Actions → Installation and speech protocol](https://github.com/MrDary-art/Mirnaya-Mafia/actions/workflows/installation.yml).
Публикация выполняется только после успешных проверок Windows и Ubuntu.

### Быстрая команда Windows

Откройте PowerShell **от имени администратора**. Команда скачивает именно
указанный релиз, затем открывает мастер. Она не содержит вашего ключа или пароля.

```powershell
$ErrorActionPreference = 'Stop'; $release = 'https://github.com/MrDary-art/Mirnaya-Mafia/releases/download/install-v2026.09.28.3'; $zip = 'arena-install-v2026.09.28.3.zip'; Invoke-WebRequest -UseBasicParsing "$release/install-windows.ps1" -OutFile "$env:TEMP/arena-install-windows.ps1"; Invoke-WebRequest -UseBasicParsing "$release/$zip.sha256" -OutFile "$env:TEMP/arena-install.sha256"; $sha = ((Get-Content -Raw "$env:TEMP/arena-install.sha256").Trim() -split '\s+')[0]; powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP/arena-install-windows.ps1" -BundleUrl "$release/$zip" -BundleSha256 $sha
```

### Быстрая команда Ubuntu: сайт

Выполняйте после входа по SSH на **Ubuntu 24.04 x86_64**. Нужны права sudo.

```bash
release=https://github.com/MrDary-art/Mirnaya-Mafia/releases/download/install-v2026.09.28.3; zip=arena-install-v2026.09.28.3.zip; curl -fL "$release/install-ubuntu.sh" -o install-ubuntu.sh && sha=$(curl -fsSL "$release/$zip.sha256" | cut -d ' ' -f1) && sudo bash ./install-ubuntu.sh --bundle-url "$release/$zip" --sha256 "$sha"
```

Если команды скачивания сообщили ошибку, не продолжайте с пустой контрольной
суммой. Загрузите три файла вручную из Assets и используйте команды ниже.

## Сборка для проверки

```text
npm ci --prefix frontend
npm run build --prefix frontend
python install/build_release.py --version <версия>
```

Предварительно загрузите реальные LFS-файлы `frontend/**`. Сборка прекращается,
если находит указатель вместо ресурса. В ZIP входят собранный frontend, backend,
установщики, зафиксированные зависимости, тестовая запись и документация.
Ключи, базы пользователей, окружения, логи и веса Whisper в архив не попадают.
Whisper Tiny и Piper скачиваются установщиком с проверкой размеров и SHA-256.

## Windows 10 22H2 / Windows 11 x64

Откройте PowerShell **от имени администратора**, затем выполните одну команду,
указав настоящий ZIP и SHA-256 из файла рядом с ним:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-windows.ps1 -Bundle 'C:\Downloads\arena-<версия>.zip' -BundleSha256 '<SHA256>'
```

Эту же команду можно выполнить из `cmd.exe`. `ExecutionPolicy Bypass` относится
только к этому процессу, системная политика не меняется. Для опубликованного
архива вместо `-Bundle` поддерживается `-BundleUrl https://...` с обязательным
`-BundleSha256`. Не передавайте пароли или Authorization Key в аргументах.

Установщик использует собственный Python 3.12.12, устанавливает API и Caddy как
службы WinSW. Вход пользователя и открытый терминал для работы сайта не нужны.
Папка по умолчанию: `C:\ProgramData\MasterNegotiations`.

## Ubuntu 24.04 x86_64

Для первой команды нужен `curl`: при его отсутствии выполните `sudo apt-get update && sudo apt-get install -y curl ca-certificates`. Остальные небольшие системные утилиты установщик проверит и установит сам. Python и Node глобально не нужны.
Сохраните скрипт в файл, затем запускайте его; `curl | bash` забирает stdin у мастера.

```bash
sudo bash ./install-ubuntu.sh --bundle ./arena-<версия>.zip --sha256 <SHA256>
```

Для опубликованного архива поддерживается `--bundle-url https://...`.
Папка по умолчанию `/opt/master-negotiations`. Службы systemd запускаются при
включении машины под отдельным системным пользователем `arena`.

## Что спросит мастер

1. Локальный доступ или домен. Локальный адрес доступен только на этой машине.
2. Логин и пароль администратора (от 12 символов). Стандартного admin/admin нет.
3. Полный Authorization Key и scope GigaChat. Можно явно пропустить подключение:
   готовые сценарии останутся доступны, онлайн-ИИ — нет.
4. Мастер скачает Tiny и голос Дмитрия, обновит базу и проверит службы.

Для домена заранее настройте DNS и входящие порты 80/443. Caddy получает HTTPS
сертификат. Установщик не открывает NAT и не меняет чужие сайты. Если порты заняты,
он останавливается. Микрофон браузера работает на localhost или HTTPS.

## Обслуживание

Windows: `C:\ProgramData\MasterNegotiations\arena.cmd <команда>`.
Ubuntu: `sudo /opt/master-negotiations/arena <команда>`.

| Команда | Действие |
|---|---|
| start / stop / restart / status | Управление службами API и сайта |
| logs | Последние записи журналов |
| doctor --speech | База, frontend, файлы моделей, реальная озвучка/распознавание, доступность сайта |
| configure | Адрес административных настроек |
| backup | Согласованная копия SQLite, конфигурации и ключа шифрования |
| model --name base | Скачать Base; включение — отдельно через админку |
| reset-admin-password | Сменить пароль через локальную консоль владельца ОС |
| update --bundle `<архив>` --sha256 `<SHA256>` | Проверка архива, резервная копия, миграция, активация |

Обновление отказывается прерывать активные сессии. При ошибке миграции службы
останавливаются; код не откатывается поверх несовместимой базы автоматически.
Резервная копия содержит секреты: храните её с ограниченным доступом.
Удаление программы не реализовано; не удаляйте `data`, `private`, `backups`.

## Внешний Whisper в МИРЭА

На сайте: **Админка → Настройки → Внешний Whisper**. Укажите имя машины и создайте
одноразовый код (10 минут). Новый код заменяет предыдущий. Код показан только
один раз. На Ubuntu с выделенной GPU:

```bash
sudo bash ./install-ubuntu.sh --role whisper-worker --home /opt/arena-whisper --bundle ./arena-<версия>.zip --sha256 <SHA256>
```

Выберите одну GPU, введите публичный HTTPS-адрес сайта и код в скрытом поле.
Worker скачает large-v3-turbo, проверит настоящий speech sample и зарегистрирует
готовность. Не нужно открывать входящий порт, вводить IP МИРЭА или копировать
GigaChat-ключ на worker. Драйвер NVIDIA и выделение GPU виртуальной машине
обеспечивает администратор МИРЭА; установщик их не заменяет.

Режимы:

- **Локально**: Whisper Tiny/Base/Small на CPU сайта.
- **Авто**: готовый worker, а при сбое — локальный Whisper.
- **Только внешний**: при недоступности показывает ошибку, локально не распознаёт.

Heartbeat — 10 с, недоступность — после 30 с, long poll — 25 с, lease — 60 с,
общий дедлайн — 90 с. После принятого ответа поздний результат не заменяет его.
Отзыв доступа действует на конкретный worker. VM должна оставаться включённой.

## Ограничения и данные

Один процесс API: комнаты и очередь отчётов используют существующие локальные
блокировки. CPU-распознавание выполняется по одному заданию с ограниченной очередью.
2 CPU / 4 ГБ — целевая конфигурация, не результат нагрузочного теста. Две записи
и параллельный Piper могут увеличить задержку; измеряйте на целевом сервере.

Оригинальные записи STT лежат вне web-root: после результата удаляются, при ошибке
хранятся не более 24 часов. Комнатные записи используют прежнюю политику хранения.
Токен worker хранится на сайте только как хеш. Authorization Key зашифрован;
ключ шифрования находится в отдельном приватном файле и должен сохраняться
вместе с резервной копией. Настройки админки имеют приоритет над старым `.env`.

Аналитика читает готовые данные, не запускает платный анализ при просмотре.
Администраторы и явно помеченные демо-аккаунты исключены. Старые аккаунты без
такой отметки включаются — их назначение нельзя достоверно определить по имени.

Восстановление доставки после аварии: принятый результат STT остаётся в базе.
Если процесс остановился между игровым ответом и записью квитанции доставки,
запрос не повторяет ход автоматически: пользователь должен открыть сохранённый
разговор. Это предотвращает двойные ответы и начисления.

## Проверки, которые нельзя заменить имитацией

Перед публичной эксплуатацией нужны чистая Windows VM, Ubuntu 24.04, настоящее
получение HTTPS-сертификата, GPU МИРЭА и проверка двух одновременных пользователей.
Локальные unit/integration-тесты протокола не подтверждают GPU-производительность.

## МИРЭА: подробный порядок подключения

### 1. Подготовьте сайт

Сайт должен открываться с другого компьютера по настоящему адресу
`https://ваш-домен`. `127.0.0.1`, `localhost` и адрес домашней сети для этого
не подходят. Домен указывает на сервер сайта; Caddy автоматически получает
сертификат. В админке проверьте голос Дмитрия и запись через локальный Tiny.

### 2. Проверьте выделенную VM

Войдите на Ubuntu VM по SSH реквизитами, выданными администратором МИРЭА.
Не запускайте установщик на гипервизоре или общем физическом хосте.

```bash
cat /etc/os-release
nvidia-smi
```

Нужны Ubuntu 22.04 или 24.04, x86_64, видимая NVIDIA GPU, исходящий HTTPS
к вашему сайту, GitHub, PyPI и Hugging Face. Если `nvidia-smi` не работает,
попросите администратора предоставить GPU виртуальной машине и проверить
драйвер. Сам установщик не переустанавливает системный драйвер.

### 3. Запустите установщик worker

```bash
release=https://github.com/MrDary-art/Mirnaya-Mafia/releases/download/install-v2026.09.28.3
zip=arena-install-v2026.09.28.3.zip
curl -fL "$release/install-ubuntu.sh" -o install-ubuntu.sh
sha=$(curl -fsSL "$release/$zip.sha256" | cut -d ' ' -f1)
sudo bash ./install-ubuntu.sh --role whisper-worker --home /opt/arena-whisper --bundle-url "$release/$zip" --sha256 "$sha"
```

Установщик подготовит Python и зависимости, покажет GPU и попросит выбрать
одну. На этом этапе откройте на сайте **Админка → Настройки → Внешний Whisper**,
введите название VM и нажмите **Создать код подключения на 10 минут**.

Вернитесь в SSH-терминал: введите HTTPS-адрес сайта, затем код. Код вводится
скрыто. Если истёк — создайте новый. Не вводите сюда GigaChat Authorization Key.
Далее скачивается large-v3-turbo (~1,6 ГБ), проверяются SHA-256, GPU и реальная
тестовая запись. Не закрывайте терминал до окончания установки.

### 4. Убедитесь, что worker готов

```bash
sudo /opt/arena-whisper/arena-worker status
sudo /opt/arena-whisper/arena-worker doctor
sudo /opt/arena-whisper/arena-worker logs
```

В админке нажмите **Обновить список**. Статус «Готов к работе» появляется после
настоящего распознавания тестовой записи, а не только после регистрации.
В блоке проверки выберите внешний worker, запишите фразу и отправьте её.
После успешного теста включите режим **Внешний Whisper, при сбое — локально**
и нажмите **Применить**. Это безопаснее для учебных занятий: при отключении VM
новые записи сможет обработать Tiny на сервере сайта.

Worker запускается автоматически после перезагрузки VM. Ваш SSH-терминал можно
закрыть, но сама VM и GPU должны оставаться доступными. На GPU-машине входящий
порт для этого приложения не открывается. TURN для видеозвонков настраивается
отдельно и к распознаванию речи не относится.

### 5. Отключение и повторное подключение

Кнопка **Отозвать доступ** отключает конкретный worker на сайте. Его прежний
токен больше не принимается. Не отправляйте файл `/opt/arena-whisper/private/worker.json`
другим людям. Для переноса на другую VM создайте новый код и новую установку.

При прерванной установке повторите ту же команду с тем же архивом и папкой.
Существующий пароль и регистрация сохраняются. Если доступ уже отозван, создайте
новый код на том же сайте и выполните `sudo /opt/arena-whisper/arena-worker reconnect`.
Команда спросит новый код скрыто и сохранит прежний файл в закрытой папке.
Завершённую установку не переинициализируйте: используйте команды обслуживания.

## Частые ситуации

| Что видно | Что сделать |
|---|---|
| Страница не открывается | `arena status`, затем `arena logs`; проверьте адрес, который напечатал мастер |
| На домене нет HTTPS | Проверьте DNS, доступность 80/443 извне и журнал `arena-web`; не отключайте проверку TLS |
| Нет доступа к админке | Используйте свой логин; восстановление пароля — `arena reset-admin-password` на сервере |
| GigaChat отклоняет ключ | Нужен полный Authorization Key, правильный scope и доступная модель; Access Token сюда не подходит |
| Worker не готов | `arena-worker logs`, `nvidia-smi`, доступ VM к HTTPS сайта; код регистрации сам по себе не означает готовность GPU |
| Файлы модели не загружены | В админке **Файлы речи → Скачать**; дождитесь проверки, затем отдельно примените модель |
| Браузер не даёт микрофон | Используйте HTTPS или localhost; разрешите микрофон в браузере |
| На обновлении есть активные сессии | Завершите их и повторите обновление; не удаляйте строки базы вручную |
| Возникла ошибка миграции | Службы останутся остановлены; сохраните журналы и резервную копию, не запускайте старый код поверх новой схемы |

## Перенос существующей базы

Резервируйте исходную базу и приватные настройки перед переносом. На прежнем
сервере завершите тренировки и остановите API, чтобы новые записи не потерялись.
Для SQLite используйте `arena backup` или SQLite backup API: не копируйте только
основной `.db`, пока работают записи WAL. Переносите также файлы записей комнат,
если они нужны по вашей политике хранения.

В новой установке остановите службы, сохраните созданную установщиком базу,
поместите согласованную копию прежней базы в `data/arena.db`, затем выполните
`arena migrate` и `arena start`. Если в прежней базе уже есть зашифрованная
конфигурация, вместе с ней требуется **прежний** `private/installation.key`.
Без этого файла сохранённый Authorization Key восстановить нельзя. Проверьте
вход, старую историю, сохранённый разбор, сценарий и комнату 1×1. Миграции 0029/0030
не удаляют прежние отчёты и не меняют сохранённые пароли.

Для новой установки администратор создаётся мастером. Для перенесённой базы
используйте существующего администратора; при `admin/admin` сначала замените
стандартный пароль. Смена пароля возможна через локальную команду восстановления.

## Статус испытаний этой поставки

Локально на Windows проверены: чистое окружение Python 3.12.12 по lock-файлу,
миграция сохранённой базы 0028→0030, разделение прав, очередь/повторы/отзыв worker,
реальная озвучка Piper и CPU-распознавание Tiny через HTTP, frontend build,
упаковка/контрольные суммы, повторная распаковка в путь с кириллицей и пробелом,
синтаксис PowerShell и конфигурация Caddy. Полный запуск служб установщика на
чистых Windows/Ubuntu VM и настоящий GPU worker остаются проверкой владельца.
CI отдельно выполняет тесты на Windows и Ubuntu; его результат виден по ссылке
Actions. Проверка GigaChat в новой поставке использовала имитации ответов:
ваш настоящий ключ нужно проверить кнопкой «Проверить и сохранить».
