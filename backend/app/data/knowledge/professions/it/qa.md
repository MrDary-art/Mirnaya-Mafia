# QA / тестировщик

## Назначение
Профиль для генерации собеседований, переговорных тренировок и оценки ответов.

## Варианты названия / близкие роли
- QA Engineer
- Manual QA
- Automation QA

## Контекст профессии
Обеспечение качества через анализ рисков, тест-дизайн, проверку продукта и автоматизацию.

## Типовые обязанности
- тест-анализ
- test cases/checklists
- bug reports
- регресс
- API/UI testing
- automation по уровню
- quality risk

## Ключевые компетенции
- тест-дизайн
- приоритизация рисков
- HTTP/API
- SQL по роли
- автоматизация по вакансии
- коммуникация дефектов

## Что проверять на собеседовании
- как тестирует новую функцию
- как приоритизирует
- пример сложного бага
- что автоматизировать
- как спорит о severity

## Типовые кейсы
- Форма оплаты перед релизом
- Фича без спецификации
- Flaky autotest
- Разработчик не согласен с severity

## Признаки сильного ответа
- мыслит рисками
- выделяет границы/классы
- даёт воспроизводимый bug report
- отделяет severity от priority

## Признаки слабого ответа
- пытается проверить всё одинаково
- не умеет формулировать expected/actual
- считает QA только кликами

## Red flags
- скрытие дефекта
- конфликтность вместо доказательств
- выдуманный automation experience

## Типовые переговорные ситуации
- релиз при известных дефектах
- severity/priority
- срок тестирования
- качество vs deadline

## Уровни
- Junior QA
- Middle
- Senior/Automation
- QA Lead

## Что актуализировать через интернет
- инструменты/automation stack вакансии
- актуальные процессы компании

## Ограничения
Не превращать интервью в викторину по редким фактам. Оценивать релевантный опыт, мышление, доказательства и коммуникацию. Конкретные требования конкретной вакансии проверять по описанию вакансии и актуальному контексту.
