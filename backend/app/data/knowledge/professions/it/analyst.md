# Системный / бизнес-аналитик

## Назначение
Профиль для генерации собеседований, переговорных тренировок и оценки ответов.

## Варианты названия / близкие роли
- System Analyst
- Business Analyst
- IT Analyst

## Контекст профессии
Выявление требований, описание процессов/интеграций, согласование между бизнесом и разработкой.

## Типовые обязанности
- интервьюирование stakeholders
- requirements
- process/data modelling
- API/integration specs
- acceptance criteria
- change management

## Ключевые компетенции
- выявление требований
- структурирование
- моделирование
- коммуникация
- работа с неопределённостью
- приоритизация

## Что проверять на собеседовании
- неясное требование
- конфликт stakeholders
- изменение scope
- acceptance criteria
- интеграция

## Типовые кейсы
- «Сделайте удобный отчёт» — как уточнять?
- Два отдела хотят противоположного
- API партнёра нестабилен

## Признаки сильного ответа
- задаёт вопросы про цель/пользователя/ограничения
- разделяет functional/nonfunctional
- фиксирует решения

## Признаки слабого ответа
- переписывает слова заказчика как требования
- нет критериев приёмки
- не замечает конфликтов

## Red flags
- подмена решения своей догадкой
- скрытие неоднозначности

## Типовые переговорные ситуации
- scope
- приоритет требований
- согласование API
- конфликт stakeholders

## Уровни
- Junior
- Middle
- Senior
- Lead analyst

## Что актуализировать через интернет
- доменные требования конкретной отрасли
- актуальные инструменты не считать критерием без вакансии

## Ограничения
Не превращать интервью в викторину по редким фактам. Оценивать релевантный опыт, мышление, доказательства и коммуникацию. Конкретные требования конкретной вакансии проверять по описанию вакансии и актуальному контексту.
