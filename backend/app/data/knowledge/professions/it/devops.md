# DevOps / Platform / SRE

## Назначение
Профиль для генерации собеседований, переговорных тренировок и оценки ответов.

## Варианты названия / близкие роли
- DevOps Engineer
- SRE
- Platform Engineer

## Контекст профессии
Автоматизация delivery, инфраструктура, наблюдаемость, надёжность и эксплуатация.

## Типовые обязанности
- CI/CD
- инфраструктура
- containers/orchestration
- monitoring
- incident response
- security practices
- capacity

## Ключевые компетенции
- Linux/networking
- CI/CD
- containers
- IaC
- observability
- reliability
- incident thinking
- cloud по вакансии

## Что проверять на собеседовании
- инцидент
- deployment strategy
- rollback
- monitoring
- IaC
- секреты
- SLO/SLI по уровню

## Типовые кейсы
- Релиз ломает сервис
- Рост latency без ошибок
- Секрет попал в лог
- Нужно мигрировать без простоя

## Признаки сильного ответа
- думает о blast radius/rollback
- измеряет
- автоматизирует безопасно
- понимает failure modes

## Признаки слабого ответа
- «перезапустить всё» как основной метод
- нет rollback
- игнорирование секретов/наблюдаемости

## Red flags
- опасные production-действия без проверки
- сокрытие инцидентов
- выдуманный опыт

## Типовые переговорные ситуации
- скорость релиза vs надёжность
- ресурсы инфраструктуры
- приоритет техработ

## Уровни
- Junior/Operations
- Middle DevOps
- Senior/SRE
- Platform Lead

## Что актуализировать через интернет
- актуальная cloud/container/IaC экосистема вакансии
- конкретные требования инфраструктуры

## Ограничения
Не превращать интервью в викторину по редким фактам. Оценивать релевантный опыт, мышление, доказательства и коммуникацию. Конкретные требования конкретной вакансии проверять по описанию вакансии и актуальному контексту.
