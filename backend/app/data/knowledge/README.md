# Knowledge Base — «Арена переговоров»

Эта папка — база знаний для генерации и оценки переговорных тренировок.

## Как использовать

Перед созданием новой тренировки система должна определить:

1. тип ситуации;
2. роль игрока;
3. роль оппонента;
4. профессию и специализацию;
5. уровень пользователя;
6. отрасль;
7. цель;
8. сложность;
9. особые условия.

После этого система извлекает только релевантные материалы:

- `negotiations/` — методики переговоров и правила оценки;
- `professions/` — профессиональные компетенции, типовые интервью, кейсы и критерии ответов;
- `scenarios/` — структура конкретного типа переговорной ситуации.

Не следует передавать модели всю базу целиком на каждый ход. Предпочтительный режим — retrieval/RAG: обычно достаточно 4–10 релевантных фрагментов.

## Web-актуализация

Интернет используется как дополнительный источник, если:

- профессия/специализация отсутствует;
- стек, инструменты или рынок быстро меняются;
- пользователь назвал конкретную компанию или вакансию;
- нужны актуальные требования российского законодательства;
- нужны действующие профессиональные стандарты, лицензирование или сертификация;
- локальная база содержит пометку `[требует проверки]`.

База знаний остаётся основой. Web не должен каждый раз заново определять BATNA, TKI, SPIN и другие устойчивые методики.

## Правила качества

- Не выдумывать факты, сертификаты, обязанности и нормативные требования.
- Не использовать TKI как диагноз личности.
- Не считать игровые метрики психометрическими шкалами.
- BATNA/ZOPA использовать только там, где они реально определимы.
- Для медицинских и юридических сценариев оценивать прежде всего коммуникацию; конкретные советы и нормы требуют отдельной проверки.
- Для найма не использовать дискриминационные характеристики как критерий успешности.
- Профессиональное интервью не должно превращаться в викторину по редким фактам. Оцениваются релевантные компетенции, мышление, доказательность, коммуникация и качество решений.

## Рекомендуемый pipeline

`User request → profession retrieval → scenario retrieval → negotiation methods → web refresh if needed → session brief → dialogue → deterministic scoring → report`
