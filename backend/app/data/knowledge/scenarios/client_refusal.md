# Отказ клиенту

## Назначение
Корректно отказать в невозможном/неподходящем запросе, сохранив отношения.

## Типовые роли
- представитель компании
- клиент

## Интересы сторон
- компания: границы/качество/риск
- клиент: получить результат

## Возможные скрытые цели
- найти альтернативу
- проверить истинную потребность
- сохранить отношения

## Базовая последовательность
- выслушать
- уточнить цель
- объяснить ограничение
- предложить альтернативы
- реакция
- выбор
- фиксация

## Критичные метрики
- Trust
- EQ
- Goal

## Грубые ошибки
- холодное «нет» без объяснения
- ложное обещание
- обвинение клиента

## Сильные ходы
- эмпатия
- ясная граница
- альтернативный путь

## Варианты
- невозможный срок
- неподдерживаемая функция
- исключение из правил
- ограниченный ресурс

## Правила генерации
- 6–8 шагов.
- На каждом шаге 3–4 ответа игрока.
- Дельты Trust/Goal/Control/EQ в диапазоне -6..+6.
- Каждый ответ должен менять либо состояние, либо информацию, либо отношения.
- Минимум три различимых финала.
- Сценарий должен быть проходимым.
- BATNA/ZOPA задавать только при наличии достаточных фактов.
- Реплики должны быть разговорными, без академической сухости.
- Оценка профессиональной части берётся из соответствующего файла `professions/`.
- Переговорная оценка берётся из `negotiations/`.

## Ограничения
Не подменять профессиональную оценку личными симпатиями. Актуальные юридические требования проверять отдельно, если они существенны для сценария.
