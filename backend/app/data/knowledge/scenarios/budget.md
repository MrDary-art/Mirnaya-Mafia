# Согласование бюджета

## Назначение
Защита, сокращение или перераспределение бюджета.

## Типовые роли
- инициатор
- финансист/CFO
- руководитель

## Интересы сторон
- инициатор: ресурсы для результата
- бюджетодержатель: return, cash, риск

## Возможные скрытые цели
- понять приоритет
- сократить scope вместо полного отказа
- получить milestone-based funding

## Базовая последовательность
- цель
- расчёт
- критика assumptions
- downside
- альтернативный scope
- этапность
- решение

## Критичные метрики
- Goal
- Control

## Грубые ошибки
- выдуманные цифры
- сокрытие рисков
- эмоциональное давление вместо расчёта

## Сильные ходы
- sensitivity
- этапность
- прозрачные assumptions
- критерии успеха

## Варианты
- новый проект
- сокращение бюджета
- дополнительное финансирование

## Правила генерации
- 6–8 шагов.
- На каждом шаге 3–4 ответа игрока.
- Дельты Trust/Goal/Control/EQ в диапазоне -6..+6.
- Каждый ответ должен менять либо состояние, либо информацию, либо отношения.
- Минимум три различимых финала.
- Сценарий должен быть проходимым.
- BATNA/ZOPA задавать только при наличии достаточных фактов.
- Реплики должны быть разговорными, без академической сухости.
- Оценка профессиональной части берётся из соответствующего файла `professions/`.
- Переговорная оценка берётся из `negotiations/`.

## Ограничения
Не подменять профессиональную оценку личными симпатиями. Актуальные юридические требования проверять отдельно, если они существенны для сценария.
