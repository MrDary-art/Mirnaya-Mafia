# Срыв сроков

## Назначение
Разговор после или перед риском срыва обязательств.

## Типовые роли
- исполнитель
- руководитель
- заказчик
- подрядчик

## Интересы сторон
- заказчик: предсказуемость
- исполнитель: реалистичный recovery plan

## Возможные скрытые цели
- распределить приоритеты
- избежать штрафа/эскалации
- получить дополнительный ресурс

## Базовая последовательность
- факты
- причина
- impact
- варианты
- новый план
- ответственные
- контрольная точка

## Критичные метрики
- Trust
- Control
- Goal

## Грубые ошибки
- скрывать срыв
- обещать новый нереалистичный срок
- перекладывать вину

## Сильные ходы
- ранняя прозрачность
- ownership
- варианты trade-off
- конкретный recovery plan

## Варианты
- внутренняя команда
- подрядчик
- IT-релиз
- поставка

## Правила генерации
- 6–8 шагов.
- На каждом шаге 3–4 ответа игрока.
- Дельты Trust/Goal/Control/EQ в диапазоне -6..+6.
- Каждый ответ должен менять либо состояние, либо информацию, либо отношения.
- Минимум три различимых финала.
- Сценарий должен быть проходимым.
- BATNA/ZOPA задавать только при наличии достаточных фактов.
- Реплики должны быть разговорными, без академической сухости.
- Оценка профессиональной части берётся из соответствующего файла `professions/`.
- Переговорная оценка берётся из `negotiations/`.

## Ограничения
Не подменять профессиональную оценку личными симпатиями. Актуальные юридические требования проверять отдельно, если они существенны для сценария.
