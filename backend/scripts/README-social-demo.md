# Оригинальные деморолики для ленты

`create_social_demo.py` создаёт три вертикальных MP4: пауза и интересы, критерии и границы, конкретный следующий шаг. Каждый ролик — 18 секунд, 720×1280, H.264 / yuv420p, 24 кадра/с. Три сцены по шесть секунд оставляют время прочитать реплики. Звука нет: весь смысл передан текстом. Это авторские учебные примеры, не реальные диалоги, не гарантии результата и не заимствованные съёмки.

Требуются уже используемый проектом Pillow и локальные FFmpeg / FFprobe. Скрипт ничего не устанавливает. По умолчанию находит инструменты в `.cache/social-tools/ffmpeg/ffmpeg-9.0.2-essentials_build/bin`, затем в PATH. Можно передать `--ffmpeg` и `--ffprobe`. Шрифты берутся из установленных Segoe UI (Windows) или DejaVu Sans (Linux); для другого окружения укажите `--font-regular` и `--font-bold` со шрифтами с кириллицей. Одинаковые исходники, шрифты и версия FFmpeg воспроизводят оформление; SHA-256 конкретных файлов записывается в manifest.

Из корня репозитория:

```powershell
python backend/scripts/create_social_demo.py
python backend/scripts/create_social_demo.py --verify-only
```

Результат находится в `.cache/social-demo`: три MP4, девять исходных кадров PNG и `manifest.json` с характеристиками и SHA-256. По умолчанию скрипт не импортирует приложение, не открывает БД и ничего не публикует. Повторный запуск проверяет и использует уже созданные ролики; `--regenerate` явно пересоздаёт их. Каждый MP4 проходит FFprobe-проверку кодека, размеров, длительности и единственного видеопотока.

## Явная публикация

Перед этим обновите рабочую БД до миграции 0033 и сделайте согласованную резервную копию **БД вместе с private/social-media**. Используйте штатный механизм резервного копирования, а не простое копирование работающей SQLite. Проверьте, что копия читается и относится к нужной базе. Параметр `--confirm-backup` проверяет существование копии; её актуальность подтверждает оператор.

После отдельного решения опубликовать:

```powershell
python backend/scripts/create_social_demo.py --verify-only --publish --author EXISTING_DEMO_USERNAME --confirm-backup C:/absolute/path/to/verified-backup
```

Рабочие `DB_PATH`, `DATA_DIR` и прочие настройки берутся из конфигурации backend. Скрипт переходит в каталог backend перед её загрузкой; при необходимости передайте обычные переменные окружения приложения. По умолчанию он требует существующую БД и существующего автора с `is_demo=1`. Учётные записи не создаются, секретные пароли и токены не требуются и в код не записываются. Оператор запускает локальную административную команду осознанно.

Для старой установки, где исходный аккаунт `demo` ещё имеет `is_demo=0`, предусмотрен отдельный **явный** флаг `--allow-legacy-demo`. Он допускает только точное имя `demo`, отсутствие прав администратора и успешную проверку стандартного публичного демовхода. Без флага такой аккаунт запрещён. Флаг не подходит другому имени, администратору или аккаунту с изменённым паролем. Он не меняет `is_demo`, пароль, профиль и прочие данные пользователя. Пример после согласованного backup: `python backend/scripts/create_social_demo.py --verify-only --publish --author demo --allow-legacy-demo --confirm-backup C:/absolute/path/to/verified-backup`.

Загрузка проходит через `ingest_upload`, публикация — через `PostIn/create_post`: настоящая проверка видео, защищённое хранилище, превью и обычные ограничения доступа. Публикации имеют аудиторию `PUBLIC`, дополнительно ограниченную приватностью профиля демоавтора. Тексты и описания явно помечены `[ДЕМО]`. Никаких лайков, просмотров, подписок, комментариев или искусственной активности скрипт не создаёт.

Идемпотентность обеспечивается стабильными метками в тексте и описании медиа и повторной проверкой под блокировкой записи SQLite. Повторный запуск не меняет время публикации и не восстанавливает удалённые или скрытые посты. Незавершённая загрузка повторно используется. Если вручную удалить метки **и из текста, и из описания медиа**, распознавание старой публикации будет потеряно. Скрипт не включён в startup, миграции или автосидирование.

Чтобы убрать демо, удалите его обычной кнопкой удаления поста от автора либо используйте штатную модерацию. Не удаляйте файлы хранилища вручную: их очищает существующий процесс с учётом ссылок и резервного копирования.

Проверка публикации использует отдельную временную SQLite-базу и синтетическое тестовое видео: `cd backend; python -m pytest -q tests/test_social_demo.py`. Проверяются отказ для обычного аккаунта, отсутствие записи без подтверждения, три настоящие загрузки, повторный запуск без дублей и сохранение удалённого состояния. Тест с видео пропускается, если FFmpeg/FFprobe не установлены; инструменты автоматически не скачиваются.
